* [[file:../intro.org::O desenvolvimento de interfaces gráficas é difícil][intro: O desenvolvimento de interfaces gráficas é difícil]], p. 75 e 79 (o código do avesso)
- Frase: “Uma das razões é o código escrito do avesso (/inside-out/),
  dividido em sub-rotinas que o /toolkit/ chama quando ocorrem ações do
  usuário (Myers, 1994, p. 75 e 79).”
- Trecho: na p. 75, no quadro “No Silver Bullet”: “User interfaces are
  especially hard to implement because: [...] they are reactive and must
  be programmed from the ‘inside-out’”. Na p. 79: “One big difference is that modern user interfaces must be
  written ‘inside-out.’ Rather than structuring the code so that the
  application is in control, as is usually taught in computer science
  classes, the application must instead be structured as many subroutines
  which are called by the user interface tool kit when the user does
  something. This is sometimes called ‘event-based programming.’”
- Lido em: =tmp/fontes/myers1994.pdf=, p. 7 do PDF (páginas 73 a 83 na
  publicação, sem número impresso por página).
- Observação: a p. 75 sustenta “Uma das razões” (da dificuldade da
  implementação); a p. 79, a descrição. Em 2026-10-14, a frase saiu do
  parágrafo do estado, onde era “Outra” das principais diferenças, para o
  da dificuldade. A explicação da inversão de controle foi para prog.org
  na rodada 2 do corte.
- Lido em, p. 75: =tmp/fontes/myers1994.pdf=, p. 3 do PDF.
- Conferido: 2026-10-06; a p. 75, em 2026-10-14.
* [[file:../prog.org::No projeto da interface, além dos][prog: No projeto da interface, além dos]], p. 75 (projeto)
- Frase: “No projeto, além dos problemas comuns a todo sistema de software
  complexo, os /designers/ lidam com tarefas e domínios complexos e têm
  dificuldade de pensar como o usuário (Myers, 1994, p. 75).”
- Trecho: “in addition to the difficulties associated with designing any
  complex software system, user interfaces add the following problems:
  designers have difficulty thinking like users; tasks and domains are
  complex” (seção “No Silver Bullet”, p. 75)
- Lido em: =tmp/fontes/myers1994.pdf=, p. 3 do PDF (p. 75).
- Observação: é o contraste entre projeto e implementação que Kiss (2014,
  p. 5) faz citando o relatório técnico de Myers de 1993, a versão
  anterior deste artigo.
- Conferido: 2026-10-12.
* [[file:../prog.org::No projeto da interface, além dos][prog: No projeto da interface, além dos]], p. 75, 79 e 80 (robustez)
- Frase: “Também precisa ser robusto: tratar qualquer entrada sem parar de
  funcionar e, como o usuário espera, permitir que ele cancele e desfaça a
  maioria das ações (Myers, 1994, p. 75, 79 e 80).”
- Trecho: “the software must be especially robust while supporting
  aborting and undoing of most actions” (p. 75); “Users expect to be able
  to abort and undo actions (for example, by typing control-C or
  Command-dot).” (p. 79); “the software that handles the users’ inputs has
  especially stringent requirements because all inputs must be gracefully
  handled. [...] the user interface must always accept any possible input,
  and continue to operate. [...] user interfaces should allow the user to
  abort and undo operations.” (seção “Need for Robustness”, p. 80)
- Lido em: =tmp/fontes/myers1994.pdf=, p. 3, 7 e 8 do PDF (p. 75, 79 e
  80).
- Observação: Myers põe o desfazer ao lado da robustez, e não como
  consequência dela; o porquê do desfazer, na p. 79, é a expectativa do
  usuário.
- Conferido: 2026-10-13.

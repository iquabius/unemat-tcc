* [[file:../modelos.org::A \[\[gls:pf\]\] se chama assim porque][modelos: A PF se chama assim porque]], p. 289:1 (o componente como função)
- Frase: “O componente do React segue essa ideia: é uma função que,
  idealmente, chamada com os mesmos argumentos, exibe a mesma tela (Lee;
  Ahn; Yi, 2025, p. 289:1).”
- Trecho: “A React component is a function that serves as a declarative
  specification of a UI [...]. Ideally, when a component is called with
  the same arguments, it should render the same interface” (289:1)
- Lido em: =acervo/lee2025.pdf=, cópia do arXiv com a paginação da ACM,
  p. 1.
- Observação: a introdução cita o mesmo trecho; aqui ele liga a função pura
  ao componente.
- Conferido: 2026-11-01.

* [[file:../modelos.org::O mesmo texto de programa também pode ter][modelos: O mesmo texto de programa também pode ter]], p. 289:38 (o JSX no React e no Solid)
- Frase: “o React reexecuta o componente quando o estado se altera, e o
  Solid atualiza só os trechos da tela que dependem dele (Lee; Ahn; Yi,
  2025, p. 289:38; SolidJS, 2026).”
- Trecho: Tabela 2, “Comparison of reactive UI frameworks”: “Re-read
  Spec.” é “Yes” no React e “No” no Solid; a propriedade é “whether they
  re-read component specifications for re-rendering” (289:38).
- Lido em: =acervo/lee2025.pdf=, p. 38 do PDF (apêndice C).
- Observação: a mesma afirmação de =comparacao.org=, “O núcleo tem duas
  tecnologias”, conferida ali em 2026-10-31.
- Conferido: 2026-11-01.

* [[file:../intro.org::Nas tecnologias que este trabalho compara][intro: Nas tecnologias que este trabalho compara]], p. 289:1 e 289:2 (as declarativas)
- Frase: “Nas declarativas, ele descreve a tela em função do estado, e o
  ambiente de execução a mantém atualizada (Lee; Ahn; Yi, 2025, p. 289:1
  e 289:2) [...]”. Até 2026-11-01, “Nos declarativos, o programador
  descreve [...] (Lee; Ahn; Yi, 2025, p. 289:1 e 289:2; SolidJS, 2026)”;
  no corte da introdução, os três parágrafos dos modos viraram um, e o
  Solid saiu da introdução (decisão do autor).
- Trecho: “A React component is a function that serves as a declarative
  specification of a UI, which is read by the React runtime to render the
  interface.” (289:1); “the same component is called for both creating a new
  view and updating an existing view” (289:2).
- Lido em: =acervo/lee2025.pdf=, p. 1 e 2 do PDF (paginação da ACM impressa
  na cópia do arXiv).
- Observação: substitui Sperber e Schlegel (2025, p. 32), cujo trecho cobria
  o React pelo MVU e o Angular pelo pré-processador; com o Angular fora da
  análise, e com a fronteira entre os dois declarativos apoiada em Lee, Ahn
  e Yi (289:38; decisão do autor de 2026-10-20), a frase fica com o React
  por esta fonte e o Solid pela documentação dele. Em 2026-10-28, a frase
  mudou na checagem adversarial: a citação ganhou a p. 289:2, sobre a
  criação e a atualização da tela.
- Conferido: 2026-10-24; de novo em 2026-10-28.
* [[file:../comparacao.org::O núcleo tem duas tecnologias][comparacao: O núcleo tem duas tecnologias]] (o React reexecuta), p. 289:38
- Frase: “quando o estado se altera, o React reexecuta o componente
  inteiro (Lee; Ahn; Yi, 2025, p. 289:38; SolidJS, 2026), a propagação
  por re-renderização.”
- Trecho: Tabela 2, “Comparison of reactive UI frameworks”: “Re-read
  Spec.” é “Yes” no React e “No” no Solid e no Angular; a propriedade é
  “whether they re-read component specifications for re-rendering”
  (289:38).
- Lido em: =acervo/lee2025.pdf=, p. 38 do PDF (apêndice C).
- Observação: até 2026-10-31, o React e o Solid estavam numa frase só,
  com a citação “289:38” sem o “p.”.
- Conferido: 2026-10-09; de novo em 2026-10-31.

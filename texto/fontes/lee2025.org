* [[file:../intro.org::Nos declarativos, o programador descreve a tela][intro: Nos declarativos, o programador descreve a tela]], p. 289:1 (o componente é uma função)
- Frase: “No React, é o próprio componente, uma função que especifica a
  tela e que, chamada com os mesmos argumentos, deve exibir a mesma
  interface (Lee; Ahn; Yi, 2025, p. 289:1, 289:2 e 289:6) [...]” Em
  2026-10-15, a função deixou de definir o modelo e passou a valer só para
  o React: o declarativo por re-renderização se define pelo que se
  reexecuta, a função ou o método que monta a tela, porque o componente
  do Lit é uma classe (checagem adversarial, decisão do autor).
- Trecho: “A React component is a function that serves as a declarative
  specification of a UI [...]. Ideally, when a component is called with the
  same arguments, it should render the same interface”.
- Lido em: =acervo/lee2025.pdf=, cópia do arXiv com a paginação da ACM.
- Observação: o “specification of a UI” é a definição do componente no
  declarativo por re-renderização; a frase saiu do parágrafo do
  declarativo, que deixou a introdução em 2026-10-14, e se fundiu com a do
  modelo (Moseley e Marks, 2006, usam “declarativo” sem definição,
  checagem de 2026-10-08).
- Conferido: 2026-10-09.
* [[file:../intro.org::Nos declarativos, o programador descreve a tela][intro: Nos declarativos, o programador descreve a tela]], p. 289:2 e 289:6
- Frase: a mesma da entrada anterior; as p. 289:2 e 289:6 sustentam que o
  ambiente de execução chama de novo o componente do React a cada
  alteração de estado (“No /declarativo por re-renderização/, o ambiente
  de execução chama de novo, a cada alteração de estado, a parte que monta
  a tela. No React, é o próprio componente [...]”). “A parte que monta a
  tela” é redação do autor (2026-10-15), no lugar de “a função ou o
  método”.
- Trecho: “the same component is called for both creating a new view and
  updating an existing view” (289:2); “setting state within an Effect
  triggers the runtime to Check if the state has changed, which is
  implemented by invoking the component body again. If the state whose
  setter function is called is actually modified, the component
  re-renders” (289:6).
- Lido em: =acervo/lee2025.pdf=, p. 2 e 6 do PDF (paginação da ACM
  impressa na cópia do arXiv).
- Observação: substitui Meta (2026b), documentação do React (decisão do
  autor em 2026-10-09).
- Conferido: 2026-10-09.
* [[file:../intro.org::Nos declarativos, o programador descreve a tela][intro: Nos declarativos, o programador descreve a tela]], p. 289:2 (o contador)
- Frase: “Num contador, por exemplo, o /callback/ do clique soma um ao
  estado, e o componente devolve o botão com o valor novo (Lee; Ahn; Yi,
  2025, p. 289:2).”
- Trecho: o =Counter= da p. 289:2: “const [s, setS] = useState(() => x);
  const h = () => setS((s) => s+1); return <button onClick={h}> {s}
  </button>”; “setS must be used to update the state.”
- Lido em: =acervo/lee2025.pdf=, p. 2 do PDF (paginação da ACM
  impressa na cópia do arXiv).
- Observação: fecha o parágrafo dos declarativos com a ilustração, depois
  da frase de Sperber e Schlegel (2025, p. 32) de que, no React, o
  /callback/ altera o estado e a tela se monta de novo (reescrita dos §5 a
  §7 na checagem adversarial de 2026-10-15).
- Conferido: 2026-10-15.

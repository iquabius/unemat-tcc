* [[file:../intro.org::Nos declarativos, o programador descreve a tela][intro: Nos declarativos, o programador descreve a tela]], 289:1 (o componente é uma função)
- Frase: “No /declarativo por re-renderização/, o componente é uma função
  que especifica a tela e que, chamada com os mesmos argumentos, deve
  exibir a mesma interface; cada alteração de estado o reexecuta, como no
  React (Lee; Ahn; Yi, 2025, 289:1, 289:2 e 289:6).”
- Trecho: “A React component is a function that serves as a declarative
  specification of a UI [...]. Ideally, when a component is called with the
  same arguments, it should render the same interface”.

- Observação: o “specification of a UI” é a definição do componente no
  declarativo por re-renderização; a frase saiu do parágrafo do
  declarativo, que deixou a introdução em 2026-10-14, e se fundiu com a do
  modelo (Moseley e Marks, 2006, usam “declarativo” sem definição,
  checagem de 2026-10-08).

* [[file:../intro.org::Nos declarativos, o programador descreve a tela][intro: Nos declarativos, o programador descreve a tela]], p. 289:2 e 289:6
- Frase: “No /declarativo por re-renderização/, cada alteração de estado
  reexecuta o componente, como no React (Lee; Ahn; Yi, 2025, p. 289:2 e
  289:6).”
- Trecho: “the same component is called for both creating a new view and
  updating an existing view” (289:2); “setting state within an Effect
  triggers the runtime to Check if the state has changed, which is
  implemented by invoking the component body again. If the state whose
  setter function is called is actually modified, the component
  re-renders” (289:6).
- Lido em: =tmp/fontes/lee2025.pdf=, p. 2 e 6 do PDF (paginação da ACM
  impressa na cópia do arXiv).
- Observação: substitui Meta (2026b), documentação do React (decisão do
  autor em 2026-10-09).
- Conferido: 2026-10-09.

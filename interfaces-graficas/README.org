#+TITLE: Implementações das interfaces

Cada interface do /benchmark/ de notação tem uma pasta, e cada
tecnologia uma subpasta, num de três grupos: =nucleo/=, o conjunto
analisado, com o núcleo (o Web Component e o React); =entorno/=, o
entorno do núcleo (o Lit e o Solid); e =fora/=, o Web Component com
/signals/, que saiu da análise com o código mantido:
=interfaces-graficas/<interface>/<grupo>/<tecnologia>/=. Os três ficam
ao lado do domínio, das cenas, das capturas e do teste de conformidade
da interface, que valem para eles, e os comandos abaixo percorrem os
três. Cada subpasta é um projeto completo, com o
próprio =package.json=, e pode ser lida sozinha. O escopo (interfaces e
tecnologias) está nas decisões em [[file:../docs/adr/][docs/adr/]]. O
código que o autor escreveu à mão no CodeSandbox, antes das
implementações, fica congelado em
[[file:autorais/README.org][autorais/]], fora dos comandos abaixo. O que
saiu da análise (a Lista filtrável, o Carrinho, o jQuery, o Angular, o
JavaFX, o Qt, o Android, o desktop, o Lit do conjunto antigo, o Quadro
de tarefas e o conversor de moedas) saiu também do repositório em
2026-10-25, e o =git log= o recupera.

* Pré-requisito: Node.js

  A versão fica em =.tool-versions=, na raiz do repositório, e o
  [[https://asdf-vm.com][asdf]] a instala:

  #+begin_src sh
  asdf plugin add nodejs
  asdf install
  #+end_src

* Instalar e rodar

  Os projetos web são /workspaces/ do npm, todos em TypeScript: um único
  =npm install= em =interfaces-graficas/=, onde está o =package.json= dos
  /workspaces/, instala todos. Os comandos =npm= abaixo rodam de
  =interfaces-graficas/=. O =build= confere os tipos com =tsc= antes de
  empacotar.

  #+begin_src sh
  npm install
  npm run dev -w reserva-de-passagem/nucleo/react
  #+end_src

  Troque o caminho pelo da implementação desejada. O Vite serve em
  =http://localhost:5173=.

  | Subpasta                     | Tecnologia                                               |
  |------------------------------+----------------------------------------------------------|
  | =nucleo/web-component=       | DOM puro com /custom element/ (classe)                   |
  | =nucleo/react=               | React                                                    |
  | =entorno/lit=                | o Web Component, com o /template/ do Lit e o =render()=  |
  | =entorno/solid=              | Solid (/signals/)                                        |
  | =fora/web-component-signals= | o Web Component, com os /signals/ do =solid-js=, sem JSX |

* Capturas de tela

  Cada interface guarda capturas versionadas em
  =interfaces-graficas/<interface>/capturas/=, uma por tecnologia e cena
  (=react-inicial.png=, =solid-ordem.png=...). Ao criar ou alterar uma
  implementação, gere-as de novo e inclua no mesmo commit: o =git diff=
  mostra o que mudou na tela.

  #+begin_src sh
  npx playwright install chromium-headless-shell   # só na primeira vez
  npm run capturas                                  # todos
  npm run capturas -- reserva-de-passagem           # uma interface
  npm run capturas -- reserva-de-passagem/react     # uma implementação
  npm run capturas -- --conferir                    # só compara, não grava
  #+end_src

  O =--conferir= gera as imagens numa pasta temporária, compara com as
  versionadas e lista as que mudaram, as novas e as que sumiram, saindo com
  erro se houver alguma. Rode antes de commitar uma alteração numa
  implementação: se algo mudou de propósito, regenere; se não, é regressão.

  As cenas de cada interface ficam em
  =interfaces-graficas/<interface>/cenas.mts= (ações do Playwright antes
  da captura); sem ele, só o estado inicial é capturado. O /script/
  ([[file:capturar.mts][interfaces-graficas/capturar.mts]]) faz o /build/,
  serve o resultado, fixa a data em 26/09/2026 (para "hoje" não mudar a
  imagem) e, no fim, avisa se a mesma cena saiu diferente entre as
  tecnologias de uma interface, o que indica que alguma implementação foge
  da especificação.

  Agentes de código seguem essas regras pelo
  [[file:AGENTS.md][interfaces-graficas/AGENTS.md]] (o =CLAUDE.md= ao lado
  é um /symlink/ para ele).

  As imagens dependem das fontes instaladas: geradas noutra máquina,
  podem mudar sem que o código tenha mudado.

* Teste de conformidade

  O =teste-de-conformidade.js= de cada interface confere a implementação
  aberta no navegador, colado no console. O mesmo arquivo roda por um
  comando, com os filtros das capturas:

  #+begin_src sh
  npm run conformidade                                # todas
  npm run conformidade -- reserva-de-passagem         # uma interface
  npm run conformidade -- reserva-de-passagem/react   # uma implementação
  #+end_src

  O /script/
  ([[file:conformidade.mts][interfaces-graficas/conformidade.mts]]) faz o
  /build/, abre a página no Chromium do Playwright, avalia nela o teste e
  imprime as linhas. Sai com erro se alguma disser =FALHOU=, se nenhuma
  disser =ok=, se o teste lançar erro ou se a interface não tiver teste.

* Especificação das interfaces (OpenSpec)

  A especificação de cada interface fica em
  =interfaces-graficas/openspec/specs/<interface>/spec.md=, no esquema
  /spec-driven/ do [[https://openspec.dev][OpenSpec]] (1.14.1, fixado em
  =package.json=): requisitos e cenários, em português, com os cabeçalhos
  que o OpenSpec lê em inglês. A mudança entre rodadas é uma pasta em
  =interfaces-graficas/openspec/changes/=, com a proposta e o /delta
  spec/; arquivada, ela se funde na especificação viva e vai para
  =changes/archive/=. A mudança dentro de uma rodada edita o =spec.md=
  direto. A convenção está no
  [[file:AGENTS.md][interfaces-graficas/AGENTS.md]].

  #+begin_src sh
  npm run conferir-especificacao          # validate e cenários × testes
  npm run openspec -- new change <nome>   # cria a pasta de uma mudança
  npm run openspec -- show <nome>         # mostra uma spec ou mudança
  npm run openspec -- archive <nome> --yes
  #+end_src

  O =npm run openspec= desliga a telemetria do OpenSpec
  (~OPENSPEC_TELEMETRY=0~), que vem ligada; o comando =openspec= direto a
  envia.
